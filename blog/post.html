用一组设计令牌，把三个页面锁进同一套皮肤

这篇是站的样板文章，正文讲的正是首页、博客、文档三页共用一份令牌的取舍。

三个页面共用一份令牌表，听起来像洁癖，实际是维护成本的问题：页面一变多，最先冒出来的通常不是功能，是偏差。

先定词，再定值#

令牌的第一步不是挑颜色，是把数量封住。背景三档、文字三档、分隔线两档、强调色一档；几何只剩一个 --radius，值固定 8px；间距压成 4 到 128 的十级阶梯，中间不再临时插值。数量定下来之后，讨论就从「这个灰好不好看」变成「这一层该用哪一档」，后者通常三十秒就能吵完。

命名也得提前想清楚。--fg-2 说的是「第二级文字」，不是「浅灰」；名字里一旦带颜色，换主题时就得连名字一起改。三个页面的起点都是下面这段： 

:root {
  /* 色彩：背景三档、文字三档、强调色一档 */
  --bg: #FFFFFF;
  --bg-raised: #FAF9F6;
  --bg-elevated: #F4F2ED;
  --fg: #24211D;
  --fg-2: #57534E;
  --line: #DEDAD2;
  --accent: #002FA7;
  --accent-wash: rgba(0, 47, 167, .10);

  /* 几何：全站只有一个圆角 */
  --radius: 8px;
}

这三页共用 theme.css，页面里不许再写死颜色。想加一档，就得先说服另外两页一起加，这个成本大多数时候刚好够劝退临时起意。

锁死圆角，只留一个强调色#

圆角是最容易失控的一类值。它不参与布局，改起来几乎没有代价，于是每加一个组件就会顺手多出一个 6px 或 10px。三个页面写完，八个圆角彼此差一两个像素，眼睛说不上哪里不对，只觉得不整齐。锁成 8px 之后它退化成常量，CSS 里也再写不出第二个值。

值收敛之后，讨论才会回到规则本身，而不是停在审美上。

强调色同理。全站只有克莱因蓝一个，允许出现的地方也只有三处：

  • 可点击元素在 hover 与 focus 时的状态
  • 当前页，以及当前所在的位置
  • 需要被记住的那一两个词

第二种颜色一进来，前两件事立刻互相稀释，读者分不清哪个能点、哪个更重要。层级不靠颜色堆，靠留白和更细的边框。

白底上，用边框和留白分层#

白色页面很容易把每块内容都做成带阴影的卡片。这个站把内容留在页面上，只给代码块等确实需要边界的区域一层暖灰底色；段落之间用留白，区域之间用 1px 的 --line。这样滚动阅读时，视线会跟着文字走，而不是被一排容器打断。 

.panel {
  border: 1px solid var(--line);
  border-radius: var(--radius);
  background: var(--bg-raised);
  /* 用 1px 边框和留白划分层级 */
  box-shadow: none;
}

顶栏收缩时保留轻微的毛玻璃，让滚动的正文经过下方时仍能看清导航。其他区域不需要投影，边框和间距已经足够。

现在这三页放在一起，按钮、日期、分割线、代码块像是同一个人写的。这不是审美统一，是约束的副产品：可选的值只有那么几个，想写歪都不容易。
